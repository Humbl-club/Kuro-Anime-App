## 7. Intake, normalisation and matching

**Pipeline.** Each handler runs inside a 50 s budget with a per-handler lock and a cursor in `import_track_state`.
1. **Raw records** go to `catalogue_source_records`, stored per source and key with a payload hash, licence and fetch time.
2. **Id links** go to `catalogue_id_links`, each with a status:
   - `accepted` means used;
   - `proposed` means waiting for corroboration or review.
3. **Compose** applies a fixed source precedence per column (`_shared/catalogue/precedence.ts`). For example, anime English title prefers Wikidata then ANN; manga format prefers MangaUpdates then Wikidata. Compose writes **shadow values** (`catalogue_shadow_values`) and never published columns. A stale shadow value is deleted when its source drops it.
4. The **comparator** RPC and report compare shadow values against today's frozen values, giving coverage, agreement and gates per group and tier.
5. **Publish**, per field group, only for groups the cutover switch sets to `new`. It snapshots first so rollback restores without blanking. The AniList-path writers skip those groups, so there is one writer per group.
6. **Create** adds titles no Kuro row has. It defaults to report mode; insert mode needs `minYear`. **Visibility** hides `list_only` titles from browse but keeps them in lists.

**Matching.** This is deterministic and explainable, not opaque "fuzzy".
- **Wikidata:** exact id crosswalk. It looks up items by the AniList id we already hold (P8729 anime, P8731 manga). An item that claims more than one Kuro title, or a title claimed by two items, links nothing and goes on the review list. Ids for other sources taken from a Wikidata item (ANN, MangaUpdates) are only *proposed*.
- **ANN and MangaUpdates title matching:**
  - **Normalisation** (`normalise_title.ts`): Unicode NFKC, lower case, Latin diacritics stripped (kana marks kept), punctuation turned into spaces, a leading "the"/"a" dropped, and season markers folded into one form (`season 2`, `2nd season`, `part 2` and roman II–X all become ` s2`).
  - **Score:**
    1. Take the best match over all of a Kuro title's names: 1.0 if the normalised names are equal, otherwise token **Jaccard** similarity.
    2. Multiply by 0.9 if either year is unknown, 0.5 if the years differ, and 0.7 if the format doesn't match.
    3. Candidates come from an exact-name index plus a token index that ignores very common tokens (document frequency above 300). At most 40 candidates are scored, and at most 3 proposals are kept.
  - **Decision:** `accepted` only when the best score is ≥ 0.92 **and** the runner-up is < 0.80. `proposed` when the best score is ≥ 0.80. Anything else is not linked.
  - A Wikidata-proposed id becomes accepted only when this matching picks the same key. If it disagrees, both stay proposed and a conflict is recorded.
- **Safety rules:**
  - Kuro ids never change, and user list rows are never touched.
  - An accepted link is never replaced: a different later candidate becomes proposed, with a conflict.
  - An adult title is never cleared without review.
  - Reads page past PostgREST's 1,000-row cap.
  - A bad item is recorded and skipped after 3 failing runs, so it cannot stall the queue.
- **PostgreSQL trigram (`pg_trgm`)** is used only in user Search (threshold 0.35), not in intake.
