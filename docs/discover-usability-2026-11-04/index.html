Discover usability pass

The owner asked for a Discover that is easier to use and more satisfying, built around where people get lost. This pass delivers the approved plan: one series once per page, a long-press preview with Plan, Seen it, Not interested, Add to club and Open, a real See all page, mood journeys, purpose lines, an end to the page, NEW marks, Essentials progress, jump links with a pinned index, ANIME / MANGA labels and telemetry. Before and after are offline fixture renders at 390 pt. Live is the signed-in dev account on the owned simulator, read-only. Nothing was pushed, deployed, applied or flagged.

Report

The branch kuro/discover-usability is local only and was not pushed. No migration was applied, no function was deployed, no flag was changed and no production data was written. The lanes were merged with --no-ff in this order: data, preview (lane B), page (lane A). Every lane worktree, lane branch and Kuro-Lane-du-* simulator has been removed. The binding contract is CLAUDE.md Rule 6, which points to the spec (R1–R8).

Integration decisions

  • One menu. Inside a Discover section, discoverMenu(for:) now gives every card lane B's discoverTitleMenu: the lifted preview plus Plan · Seen it / Already read · Not interested · Add to club… · Open. The same actions are VoiceOver custom actions. Outside the page, cards keep the shipped frame menu. The section id, reason and name come from the page's section context.
  • One toast slot (D12). The page installs discoverPageHost, lane B's discoverFeedbackHost plus the page's bookkeeping. The stacked tastePlanHost and lane A's interim toast bar are gone.
  • Tallies are counted once. Lane B's controller records each answer and sends its event. It then reports to the page through onHidden and a new onUndone hook, so the end block, the visit-end deltas and the "nothing done yet" rebuild guard stay right. Plan results are read from TastePlanController.lastResult (deduplicated by token), not from the toast text. Menu plans are reported as via: menu.
  • Plan keys stamp on a confirmed add and restore on a failure (stampsOnConfirm, R4).
  • See all opens DiscoverSeeAllPage for every routed section. Because-you rows arrive as generic media and are converted to catalogue cards. Tonight's shelf has no route and sits behind discover_realm_rails_v1 (0% live), so it keeps the old grid; FullMangaSectionView is deleted.
  • Moods open DiscoverMoodRoute (ids discover:mood:<raw>). The interim mood page and the bridge are deleted.
  • Fixes made during integration:
    • The test graph's TasteStore now uses the graph's defaults, so hidden titles no longer leak between tests through UserDefaults.standard. Both lanes flagged this.
    • Account deletion now also removes the account's "new since your last visit" ledger.
    • "Over 50 episodes" was asking for the data lane's 27+ bucket. The anime long bucket is now 51+ and standard is 14–50, in both the client and the prepared SQL (D10). Suite 87 has one more assertion (46 in total).
    • The live walk found the preview reading "Why it's here: Why it's here: in our canon." The page now passes the bare reason words, the preview adds the prefix once, and a test covers it.
    • The obsolete fold render has been retired.

  • Apply 20261104100000_discover_usability_v1.sql after review. Until then:

    • Cozy and Intense fall back to one Browse genre, so the "our picks" purpose line is not yet true.
    • Franchise dedupe uses the title-stem rule.
