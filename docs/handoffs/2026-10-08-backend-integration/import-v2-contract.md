# Import v2 frozen integration contract

Implementation baseline: the approved canonical plan and `LibraryImportWorkflow.swift` (KuroLibrary). Contract changes require lead coordination. All RPCs return snake_case objects matching those shared Codable types; `ImportValues.score_raw` is a string or null even when SQL stores numeric.

- `start_library_import_v2(p_selection jsonb,p_action_id text)` -> ImportOutcome. Selection keys: provider,source_kind,source_identity,media,statuses. One queued/running job per account/provider. v2 phase starts preparing. Replay requires identical selection.
- `prepare_import_chunk_v2(p_job_id uuid,p_items jsonb,p_exhausted_media jsonb default '{}')` -> ImportOutcome. Items <=100 are {medium,external_id,title?,values:ImportValues}. Stage server baseline/current snapshot, normalized incoming data and disposition. No Library writes. End-of-selected-stream flags are recorded on final source chunks. Same input repeats safely; contradictory source duplicates become source_changed review, never silently last-wins.
- `apply_import_chunk_v2(p_job_id uuid,p_action_id text,p_decisions jsonb)` -> ImportOutcome. Decisions <=100 use ImportDecision shape. Freeze action/hash per decision. Verify phase, recorded source exhaustion for all selected media, staging baseline and current revision/lifecycle. Explicit user keep and identical updates are unchanged. Each decision resolved_media_id acknowledges the exact staged target; application never remaps. A job-local manual target is staged only through prepare_import_chunk_v2 for an unresolved item and cannot override an already canonical provider match.
- `finish_library_import_v2(p_job_id uuid)` -> ImportOutcome. All selected source streams must be exhausted and all staged items terminal. Publication revisions reflect only real effects; final projection_ready initially false (native owns refresh readiness).
- `import_job_status_v2(p_job_id uuid)` -> ImportOutcome.
- `import_jobs_page_v2(p_cursor text default null,p_limit int default50)` -> ImportJobsPage, own jobs only; stable opaque cursor.
- `import_items_page_v2(p_job_id uuid,p_cursor text default null,p_limit int default50)` -> ImportItemsPage. ReviewItem keys exactly match shared contract; changed_fields use ImportField values. Default ordered stable medium/external_id cursor, never date precision loss. Counts treat source_changed as conflict; rejected invalid/unmatched are distinct.
- `cancel_library_import_v2(p_job_id uuid)` -> ImportOutcome. Owner-only account/job lock, preserve commits, idempotent.
- `undo_library_import_chunk_v2(p_job_id uuid,p_action_id text,p_cursor text default null,p_limit int default100)` -> ImportUndoOutcome. Stop active application first; guarded post-revision/lifecycle, bounded immutable receipts, cumulative reverted/skipped, next_cursor. Persist source phases undoing/undone and action identity; retry the same cursor yields the same result. Prune detail/before-images only for terminal jobs older than latest10, preserving summary and history_available=false.

Server jobs retain original state column compatibility and gain contract_version=2 plus phase/selection/exhaustion/history metadata as needed. v1 cannot apply to v2 jobs. Review counts: pending includes new/existing/changes; conflict includes source_changed. Terminal SQL outcome defaults projection_ready=false; native overlays true only after required Library and selected Home projections are confirmed. Missing unavailable fields are represented by values.unavailable_fields and optional values.

## Agreed implementation clarifications

- ImportSourceItem additionally carries optional resolved_media_id. Prepare may install a job-local mapping for an unresolved item before application; it captures the actual target's current values/revision/lifecycle for fresh review. This choice is excluded from source-content duplicate hash; an already resolved provider identity cannot be overridden. Apply cannot install an unreviewed target.
- Native service additionally exposes pendingImports:[ImportManifest], discoverPendingImports(), prepareImportReviewRetry(jobId:itemIds:) (new job/fresh baseline for selected terminal unresolved items), matchImportItem(jobId:item:mediaId:) (re-prepare then fresh review).
- Native presentation owns ImportResultDestination.importedTitles(Set<MediaKey>)/fullCollection and ImportWorkflowSheet(imports:job:onNavigate:). Lead wires these callbacks at the existing pager/composition only.
- Library owns an affected-key Undo reservation and rejects competing admission on those keys while checking durable pending changes and dispatching compensation. SQL lifecycle/revision guards remain authoritative. Unrelated keys stay usable.
- Source drafts retain optional provider title for unmatched-item explanations; title never becomes tracking identity. Shared legacy checkpoint helpers remain compatible while new workflows use attributed manifests.
- Native `stopPreparedImport(actionId:) async throws` explicitly abandons and cleans a jobless local preparation; if a server job exists, it stops through the owner-authorized server contract. No invented server outcome is required.
- Manifest `undoReverted` and `undoSkipped` are optional persisted cumulative receipt counts, surfaced by the owner and restored after restart. Counts are not summed again on replay.
- Decisions acknowledge the exact staged internal target: `resolved_media_id` defaults to the review item's `media_id`. Manually matched non-deferred decisions require that target seal; a supplied canonical target must also equal the staged identity. Application never remaps.
- Optional `onActionId` preparation callbacks identify the exact mounted source gesture before awaited work. Automatic Retry uses that original identity; it cannot search by provider for an unrelated approved job.
- Optional manifest `startAttempted` is saved before admission. Stop after an uncertain admission reconciles that original action before deleting its pages.

## Library mutation sequencing

Actual Apply and Resume reserve only resolved add/update media keys through `LibraryRefreshHook.withImportMutationReservation`, delegating to Library's existing FIFO. Held prior writes settle first; durable unsent/conflicted intent prevents application. Keep/defer needs no mutating key reservation. Frozen approvals remain immutable even when dispatch is blocked. Chunks, finish and typed publication stay inside the reservation; pure terminal replay only publishes and can proceed with pending local state. The Undo compatibility alias delegates this same mechanism.
